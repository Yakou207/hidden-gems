# Hidden Gems: Exposure Allocation Efficiency and Creator Fairness in Recommender Systems

Final-year project (FYP). We study how a short-video recommender allocates exposure, and whether good videos
and their creators get the exposure their quality deserves.

## The question

On a short-video platform the recommender decides which videos are shown, and to how many people. If exposure
follows quality, the platform is efficient and creators are treated fairly. If it follows early luck instead,
some good videos stay buried ("hidden gems") and small creators lose out.

This is hard to measure because exposure and popularity come from the same algorithm. We use **KuaiRand**
(Gao et al., CIKM 2022), which mixes about 1.19 million *randomly* inserted videos into real users' feeds.
Random exposure gives each video a quality estimate that does not depend on the algorithm's earlier choices,
and we compare it with the exposure the algorithm actually gave.

Research questions:

| | Question | Status |
| --- | --- | --- |
| RQ1 | How far does algorithmic exposure deviate from unbiased quality, and how many good videos are under-exposed? | Preliminary results |
| RQ2 | How strongly does early (cold-start) exposure determine later exposure? Is creator exposure proportional to merit? | Preliminary results; causal test underpowered |
| RQ3 | What is the efficiency–fairness trade-off of exploration and cold-start policies a platform could adopt (platform governance)? | Planned |

## Current status

So far we have only used **KuaiRand-Pure**, the smallest version of the dataset (27,285 users, a pool of 7,583
videos, about 194 MB). Work done on it:

1. **Data profiling and cleaning** (`src/01`, `src/02`): duplicate log events removed, ads and posts without a
   duration flagged, missing-value codes converted. Raw data are never modified.
2. **Preliminary analysis** (`src/03`): quality = empirical-Bayes-shrunk long-view rate under random exposure,
   ranked within duration deciles (split-half reliability 0.825). Main findings so far:
   - algorithmic exposure is far more concentrated than random exposure (Gini 0.757 vs 0.053);
   - quality and exposure are only moderately related (Spearman 0.40);
   - 231 top-quartile-quality videos (13.1%) sit in the bottom exposure quartile;
   - early exposure predicts current exposure much better than quality does (correlational);
   - creators with little early exposure get far less exposure than their merit share (ratio 0.09 vs 2.25).
3. **Causal feasibility check** (`src/04`): a platform-level panel design fails its placebo test; a
   user-level randomised comparison is close to the limit of its placebo test and underpowered in Pure
   (minimum detectable effect about 38%).

Full numbers are in `reports/`. All results are preliminary.

## Next steps

- Move the analysis to **KuaiRand-27K** (the same users with all ~32 million videos they interacted with,
  about 46 GB). The random exposure still covers only the pool videos, but the full data give each video's
  share of all traffic, many more events for the causal test, and creator attributes that do not depend on
  exposure.
- Test other quality metrics (likes, follows, play-time ratio) and creator groupings unrelated to exposure.
- RQ3: evaluate exploration-share and cold-start policies offline on the random log (replay / IPS /
  doubly robust estimators) and trace an efficiency–fairness frontier.

## Layout

```
data/raw/          original archive + extracted CSVs. Read-only, never edited; scripts only read from here.
data/processed/    outputs of src/ scripts (parquet). Safe to delete and regenerate.
src/               numbered scripts, run in order
reports/           logs and figures generated by the scripts
```

## Reproduce

Download `KuaiRand-Pure.tar.gz` from the Zenodo link above into `data/raw/` and extract it there (it creates
`data/raw/KuaiRand-Pure/`), then run the scripts in order. Requires Python 3 with pandas, pyarrow, numpy,
scipy, matplotlib and tabulate.

```bash
python3 src/01_profile.py   # -> reports/01_profile.txt
python3 src/02_clean.py     # -> data/processed/*.parquet, reports/02_cleaning_log.md
python3 src/03_prelim_analysis.py  # -> reports/03_prelim_results.md, reports/figures/, data/processed/video_level.parquet
python3 src/04_feasibility_random_shock.py  # -> reports/04_feasibility.md
```

## Processed tables

- `interactions.parquet`: the three logs stacked, with `source` in {random, std_main, std_pre}.
  Added columns: `event_time` (from `time_ms`, Asia/Shanghai), `author_id`, `is_ad`,
  `duration_ms_clean`, `duration_imputed`, `play_ratio`.
- `videos.parquet`: video basic features joined with video statistics (1:1 on `video_id`), plus `is_ad`.
- `users.parquet`: user features; missing codes (-124, "UNKNOWN") converted to NA.

Cleaning decisions and counts: see `reports/02_cleaning_log.md`.
